# a-stock-trading-review

面向A股交易者的证据化每日复盘 Skill。它先判断市场和主线，再检查核心股、持仓与交易纪律，最后才用 MA、RSI9 和 BIAS20 制定具体执行位置。

> 本 README 是给使用者看的说明。实际运行规则以 [SKILL.md](SKILL.md) 和 [references/](references/) 中的文件为准。

## 能做什么

- 复盘最近一个完整A股交易日或指定交易日；
- 判断市场环境与进攻、平衡、防守状态；
- 找出当日真实赚钱效应，以报告内D ID追踪正向方向；另用R ID检查与主线、持仓和次日计划有关的重要风险方向；
- 比较强势方向的产业、趋势、盘面、容量和事件核心；对退潮方向只找风险锚；
- 检查持仓相对指数、板块和核心股的强弱；
- 验证昨日计划，评价今日交易是决策正确还是结果偶然；
- 生成0～5只无目标数量的次日交易核心池，不为凑数降低标准；另列最多3只近线淘汰和0～3只观察锚；
- 为每只交易候选制定超预期、符合预期、低于预期三种应对；
- 在最后一步计算 MA5/10/20/60、Wilder RSI9 和 BIAS20：第⑨A处理核心池，第⑨B处理未入核心池的真实风险持仓；
- 盘前只更新隔夜新增变量，不在没有新日K时重算日线指标。

## 九步复盘流程

1. 市场环境；
2. 今天赚钱效应在哪里；
3. 用“市场地位 × 生命周期”判断方向：③A承接第②全部正向D方向，③B补充第②之外的重要风险R方向；
4. 每条重点方向谁最强、为什么强；
5. 我的持仓在板块里属于强还是弱；
6. 今天自己的交易哪里做对/做错；
7. 明日核心池（0～5只，无数量目标）；
8. 对核心池每只股票写“超预期 / 符合预期 / 低于预期”怎么处理；
9. 最后才用 MA + RSI9 + BIAS20 找位置：第⑨A执行核心池，第⑨B只处理已有风险持仓。

第1～8步不能使用技术指标决定股票是否入选。技术指标只负责回答“在哪里执行”，不能替代产业逻辑、主线地位和市场强弱判断。

D与R只在单份报告内有效：D代表正向机会链，可继续进入核心池或观察锚；R代表风险链，只用于风险锚，并在涉及真实持仓时继续进入第⑤和第⑨B。R不进入核心池、观察锚，也不建立风险股票池。新启动、强化、分歧、修复和退潮都必须填写“阶段依据”。

第7步可以输出0～5只，没有正常数量。每只核心股标记“优先执行”或“条件执行”，两者都不是立即买入；条件执行只有严格超预期触发成立时才允许新增。最多补充3只最接近入池但被淘汰的候选，每只只写1个决定性原因；没有时注明“无近线淘汰候选”。第8和第⑨A不得把这些淘汰股或观察锚重新加入交易计划；第⑨B也只能收纳用户真实持仓。

第⑨A和第⑨B互斥：持仓若同时进入核心池，只在A出现，并分别说明已有仓位怎么管、是否允许新增。B只处理未入核心池但已在第⑤步确认存在退潮、掉队、逻辑受损或技术破坏的持仓，只能减仓、退出或继续观察，禁止补仓、加仓和摊低成本；没有这类持仓时，整个B区不出现。

## 快速使用

### 完整盘后复盘

```text
使用 $a-stock-trading-review 复盘最近一个完整A股交易日，并制定下一交易日计划。
```

### 指定交易日

```text
使用 $a-stock-trading-review 复盘2026年8月14日A股，并制定下一交易日的条件化交易计划。
```

### 带持仓和交易记录

```text
使用 $a-stock-trading-review 复盘今天A股。
我的持仓：股票名称、原始买入逻辑、相对成本位置。
今日交易：买卖动作、当时依据。
请检查持仓相对板块强弱，并评价交易纪律。
```

### 盘前更新

```text
使用 $a-stock-trading-review 根据上一份完整复盘做盘前更新，只检查隔夜新增变量和计划变化。
```

也可以直接使用“复盘今天A股”“检查持仓强弱”“验证昨日计划”“制定明日交易预案”等自然语言触发。

## 可以提供的输入

所有个人输入均为可选：

- 目标交易日；
- 持仓股票与原始逻辑；
- 相对成本位置，例如成本附近、小幅浮盈或小幅浮亏；
- 当日交易及当时的决策依据；
- 昨日复盘或计划；
- 希望重点检查的方向、股票、公告或研究材料。

没有提供持仓、交易或昨日计划时，Skill 会跳过相应个人评价，不会编造。

## 输出内容

完整复盘默认包含：

- 一段“先说结论”；
- 九步复盘正文；
- 0～5只无数量目标的交易核心池，以及最多3只近线淘汰候选；
- 0～3只观察锚；
- 每只交易候选的超预期、符合预期、低于预期应对；
- 趋势确认、新增买入、减仓和退出的独立条件；
- 数据来源、截止时间、完整度、冲突和已知缺口；
- 一句话次日作战计划。

没有清晰主线或高质量机会时，候选池可以为0，结论可以是观察或防守。

## 核心纪律

- 先看全市场，再研究重点方向；
- 当日行业上涨面只能证明赚钱效应，不能单独证明主线；
- 赚钱效应用宽度、核心强度、持续性、成交承载、扩散五维核对；
- 方向用市场地位与生命周期双轴判断；每个正式阶段都要有阶段依据，严重缺失时只能写“观察 × 待确认”；
- 退潮不等于市场地位立即消失，允许“主线 × 退潮”；退潮复盘只看与近期主线、持仓、高位风险和次日计划相关的方向，不扫描全部下跌板块；
- 单一公司事件不能直接外推为整个行业主线；
- 核心标签描述市场角色，“容易交易”不等于“盘面核心”；
- 股票角色不做固定排名，市场高标主要用于情绪与风险观察；
- 趋势确认不等于当前位置允许新增买入；技术指标只定位执行，不能制造风险结论；
- BIAS明显扩张或价格远离均线时，继续突破不能直接作为追涨买点；
- RSI和BIAS不能单独作为买卖理由；
- 所有计划都必须由可观察条件触发，不承诺涨跌。

## 数据与证据

Skill 会优先使用当前环境中可用的A股数据能力：

- 行情与财务数据：`a-stock-data`、`mx-data` 或本 Skill 的数据适配脚本；
- 新闻、公告与事件线索：`mx-search`；
- 订单、客户、技术、产能和产业事实核验：`a-stock-evidence-research`；
- 完整公司研究、估值和同行分析：`a-stock-investment-analysis`。

主数据源失败时只进行有限降级；无法确认的数据会标记为缺失或降低置信度，不用估算值冒充真实行情。

## 存档与隐私

存档根目录 `archive_root` 按以下优先级确定：

1. 用户在本次任务中明确指定的目录；
2. 环境变量 `REVIEW_OUTPUT_DIR`；
3. 当前 Codex 项目根目录下的 `outputs/a-stock-trading-review`。

当前项目根目录以 Codex 会话的 `cwd` 为唯一解析起点：若 `cwd` 位于 Git worktree 内，则使用 `git rev-parse --show-toplevel` 返回的 Git 顶层目录；否则直接使用 `cwd` 本身。

完整复盘保存为：

```text
<archive_root>/YYYY-MM-DD/review-HHmmss.md
```

盘前更新保存为：

```text
<archive_root>/YYYY-MM-DD/premarket-HHmmss.md
```

无论本次是否写入，都会先按上述规则解析 `archive_root`，用于查找上一份完整复盘。用户明确说“不保存”或“不要落盘”时，仅关闭本次写入：仍可读取同一 `archive_root` 中的历史复盘，但不为本次结果创建目录或文件。

选定的目录不存在时可以自动创建；若目录不可创建或不可写，不会静默切换到其他目录，而是只输出结果并说明原目标路径和失败原因。

如果希望不同 Codex 项目持续使用同一份复盘历史，建议把 `REVIEW_OUTPUT_DIR` 设置为统一存档目录。该环境变量本身就是最终 `archive_root`，不会再拼接 `outputs/a-stock-trading-review`。

默认存档会脱敏，不记录账户身份、资金总额、持仓数量、精确成本、精确成交价和精确浮盈亏比例。

## 不适用范围

本 Skill 不用于：

- 无条件荐股或承诺收益；
- 自动下单或代替用户作出交易决定；
- 单独承担完整公司深研、估值或复杂量化回测；
- 把未经核验的搜索摘要、传闻或市场观点写成公司事实；
- 在没有用户仓位模型时给出精确仓位比例。

本 Skill 输出的是条件化研究与交易计划，不构成收益承诺或自动交易指令。
